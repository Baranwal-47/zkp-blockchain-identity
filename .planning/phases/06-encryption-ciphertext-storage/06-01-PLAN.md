  <action>
    Create new file `privdId_admin/backend/crypto/aesgcm.js` as an ESM module. Import `crypto` (built-in) and `import { timed } from "../utils/timing.js"` (note the `../` — this file is one level above `utils/`). Define module constants `ALGO = "aes-256-gcm"`, `IV_LENGTH = 12`, `KEY_LENGTH = 32`.

    Export `generateDEK()`: returns `crypto.randomBytes(KEY_LENGTH)` (a 32-byte Buffer). Do NOT base64-encode here — return the raw Buffer; the caller in studentService persists it as base64.

    Export `async encryptCredential(plaintextObj, dek)`: validate `dek` is a 32-byte Buffer BEFORE entering timed() (throw `Error` if not, mirroring computeMerkleRoot's length guard). Wrap the core work in `await timed("encryptCredential", async () => { ... })`: generate `iv = crypto.randomBytes(IV_LENGTH)` INSIDE the function (never hoist/cache the IV — IV reuse under a fixed key is catastrophic for GCM), `cipher = crypto.createCipheriv(ALGO, dek, iv)`, encrypt `Buffer.from(JSON.stringify(plaintextObj), "utf8")` via `Buffer.concat([cipher.update(...), cipher.final()])`, then read `authTag = cipher.getAuthTag()` AFTER `cipher.final()` (calling getAuthTag before final is wrong). Return `{ iv: iv.toString("base64"), authTag: authTag.toString("base64"), ciphertext: ciphertext.toString("base64") }`. Unwrap the `{ out }` from timed and `return out` so callers get the bare blob.

    Export `decryptCredential(blob, dek)` (sync, no timed needed): decode `blob.iv`, `blob.authTag`, `blob.ciphertext` from base64, `decipher = crypto.createDecipheriv(ALGO, dek, iv)`, call `decipher.setAuthTag(authTag)` BEFORE `decipher.final()`, then `JSON.parse(Buffer.concat([decipher.update(ciphertext), decipher.final()]).toString("utf8"))`. Do NOT swallow errors — let a tampered-tag failure throw out of `decipher.final()`.

    Do NOT add any console.log that prints the dek, the plaintextObj, or the full blob — only the `timed()` perf line (rollNo-free here) is allowed. No fenced try/catch swallowing inside the module.
  </action>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering / Information Disclosure | `encryptCredential()` IV generation | mitigate | IV is `crypto.randomBytes(12)` generated INSIDE encryptCredential on every call — never hoisted, cached, or derived. Verified by the "fresh IV per call" assertion in Task 1's verify command. Reusing a (key, IV) pair under GCM leaks plaintext XOR and forges auth tags. |
| T-06-02 | Information Disclosure | `Student.dek` plaintext field | accept | Accepted single-custody interim gap per D-01 (documented in PROJECT.md/REQUIREMENTS.md; real Shamir 2-of-3 split is E6/deferred). Phase 7 ECIES-wraps then wipes it. |
| T-06-03 | Information Disclosure | `aesgcm.js` logging | mitigate | The module logs only the `[perf]` timing line via `timed()`; it never logs `dek`, plaintext, or the blob. Verified by the no-secret-log grep in Task 1's acceptance criteria. |
| T-06-04 | Tampering | ciphertext stored on public IPFS | mitigate | AES-256-GCM auth tag (`getAuthTag`/`setAuthTag`) detects any ciphertext tampering at decrypt time (`decipher.final()` throws). Inherent to choosing GCM; verified by Task 1's tamper-detection assertion. |
