## Next-Phase Scoping Notes (pre-discuss-phase)

This is the full diagnosis from the cleared conversation, preserved so the next session doesn't have to re-derive it.

**Current mobile flow (as it exists today):**
`LoginScreen` → `ClaimCredentialScreen` (working, this phase) → `StudentProfile` (broken: still assumes the old 5-attribute credential shape and has a DDMMYYYY date-parsing bug) → `LoadingScreen` (already migrated to the new 7-attribute `/generate-proof` contract) → `ShowProof` (787 lines) → `VerifyProof` (1300+ lines; takes `proof`/`publicSignals` directly via navigation params, not a Proof-ID lookup).

**Backend state:**
- `zkp-backend` already has `/generate-proof`, `/verify`, `/verify-onchain`, `/credential-info`, `/session/nonce` — solid foundation. But there is **no persistent Proof-ID/URL store** yet — needed for the target "Verify Proof" screen where anyone can look up a proof later by ID.
- **No on-device decrypt flow exists at all** — confirmed gap, needed for the planned "View Credentials" feature.
- Admin backend has **no `GET /credential/:rollNo/blobs`-style endpoint** yet (called for in blueprint §E3.6) to hand the two CIDs (ciphertext + envelope) to the device.

**The real architectural snag (this is the part worth protecting from re-derivation):**
The current `/session/nonce` is consumed by `/verify` — single-use, anti-replay. The target workflow wants a **stable Verification URL / Proof ID** that anyone can check repeatedly. That requires "verify by ID" to do a cryptographic re-check + registry/revocation lookup **without** re-consuming the nonce — because the nonce's job ends at proof *generation* time, not at every later lookup. Any new "verify by Proof-ID" endpoint must be designed as its own path, separate from the nonce-gated `/verify`.

**Scope being discussed for the next phase** (not yet a phase directory — needs `/gsd:discuss-phase`):
- New Dashboard screen.
- New "View Credentials" screen (on-device decrypt of the stored ciphertext using the student's private key + unwrapped DEK).
- Redesigned "Generate Proof" screen with attribute checkboxes (selective disclosure UI).
- Redesigned "Verify Proof" screen built around Proof-ID lookup (not nav-param passing).
- Deletion of dead/legacy screens: `StudentProfileScreen`, `IdentityForm`, the old 787-line `ShowProof`.
- Two new backend endpoints: admin-backend `GET /credential/:rollNo/blobs` (or similar), and zkp-backend Proof-ID persistence + lookup-by-ID verify path.

Given the size (multiple new screens, deletions, 2+ new backend endpoints, the nonce/Proof-ID architectural decision above), this was assessed as a full GSD phase, not a quick edit — hence the pause-and-replan recommendation.
