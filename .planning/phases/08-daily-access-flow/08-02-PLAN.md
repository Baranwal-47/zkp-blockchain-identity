## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SecureStore → app memory | Private key leaves Keystore/Keychain into JS memory for the unwrap call only |
| ciphertext/envelope (from IPFS) → decrypt | Untrusted/possibly-tampered blobs are fed to authenticated decryption |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | Information Disclosure | DEK / privKeyHex / plaintext leaking via logs | mitigate | Both utils forbid `console.log` of the dek, privKeyHex, or plaintext (verified by a no-`console.log` grep gate in dek.js); plaintext returned to caller only, never persisted. |
| T-08-05 | Tampering | Tampered ciphertext or DEK envelope from IPFS | mitigate | AES-GCM auth tag (gcm.decrypt throws on mismatch) and ECIES auth (eciesjs decrypt throws) both fail closed; neither util swallows the error, so a tampered blob surfaces as a thrown error, never silent garbage. |
| T-08-06 | Tampering | Using Node `crypto` shim that silently lacks GCM (Pitfall 1) | mitigate | Mandate `@noble/ciphers` gcm (pure-JS, RN-safe, pinned direct dep); the Task 1 verify command executes a real encrypt→decrypt round trip, so a non-functional cipher fails the gate rather than shipping. |
| T-08-SC | Tampering | @noble/ciphers dependency | mitigate | No NEW package — @noble/ciphers is already present transitively (in production use via eciesjs/ethers) and audited per RESEARCH.md Package Legitimacy Audit (Approved/reused).
