Stand up the real Safe 2-of-3 on Sepolia and verify the end-to-end manual-signing UX there (D-11): generate 3 fresh throwaway owner keypairs (D-02), deploy the Safe, hand the registry admin to it, and walk through a real propose -> 2 MetaMask signatures -> manual execute cycle via the Pending Approvals screen. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deployer EOA -> Sepolia Safe | One-time handoff; deployer must not be an owner |
| proposeAcceptAdmin.js -> Safe Tx Service | Pushes the acceptAdmin tx into the queue; does not itself sign with owner keys |
| 3 owner MetaMask accounts -> Safe Transaction Service | Real ECDSA signatures over the Safe tx EIP-712 hash |
| generated private keys -> filesystem/git | Throwaway keys must never be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-18 | Information Disclosure | committing the 3 throwaway owner private keys | mitigate | generateSafeOwners.js prints to stdout only, never writes a key file; keys go to MetaMask + gitignored .env; .env.example stays placeholder-only. |
| T-09-19 | Elevation of Privilege | deployer EOA accidentally added as a Safe owner, retaining unilateral influence | mitigate | D-03 separation enforced in Task 3 human-check (deployer is not an owner); Safe is strictly 2-of-3 of the fresh keys. |
| T-09-20 | Tampering / Front-running | acceptAdmin replay/front-run during handoff | mitigate | acceptAdmin only succeeds for msg.sender == pendingAdmin (the Safe); the proposed call is itself a 2-of-3 Safe tx — no single actor can complete or hijack it. proposeAcceptAdmin.js only queues the proposal; execution still requires 2 owner signatures. |
| T-09-21 | Elevation of Privilege | Execute auto-firing on the 2nd Sepolia signature (D-06 violation) | mitigate | Task 4 step 6 explicitly verifies Execute does not auto-fire and requires the manual confirm. |
| T-09-22 | Spoofing | a single official's wallet mutating registry state alone (GOV-02) | mitigate | Task 4 step 8 negative check: direct deployer-EOA / single-owner issue/revoke reverts under onlyAdmin (now the Safe). |
</threat_model>
