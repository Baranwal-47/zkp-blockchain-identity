<objective>
Build the recovery session state machine: an in-memory `Map`-backed session store, the `/api/recovery/initiate` and `/api/recovery/submit-share` endpoints, and the authentication + duplicate-role guards that gate share submission. This plan reconstructs the DEK in memory at threshold and immediately wipes it — but does NOT yet perform Case A or Case B operations (that is plan 11-02, which plugs into the `completeOperation` hook this plan defines).

Purpose: REC-01 (session open → 2 shares → in-memory reconstruct → wipe) and REC-04 (authenticated share submission) are the foundation both recovery operations build on. This plan also ships the browser UI for opening a session and submitting a share — without it there is no way to demo recovery short of hand-typing curl commands with a raw Shamir share, which defeats the entire point of RSA-wrapping the shares to begin with (`crypto/rsaShare.js`'s `unwrapShare` doc comment already says it "exists for Phase 11's client-side recovery page").
Output: recoveryService.js (session Map + reconstruct/wipe logic with a pluggable operation hook), recoveryController.js (+ getMyShare), recoveryRoutes.js, app.js mount, `erased`/`erasedAt` Student fields (added here so plan 11-03 can read them without a Student.js file conflict), recovery.smoke.mjs covering REC-01/REC-04 unit behavior, and RecoveryPage.jsx — the browser UI both the AcadAdmin (initiate) and the custodian (fetch-wrapped-share → decrypt in-browser → submit-share) use.
</objective>
