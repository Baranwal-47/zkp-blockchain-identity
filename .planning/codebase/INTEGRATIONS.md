## Blockchain

**Network:** Ethereum Sepolia testnet (production target)

**RPC Provider:**
- Admin backend (`privdId_admin/backend/services/credentialService.js`): `process.env.SEPOLIA_RPC_URL` (JsonRpcProvider — write transactions)
- ZKP backend (`zkp-backend/server.js`): `process.env.BLOCKCHAIN_RPC_URL` (hardcoded fallback: `https://eth-sepolia.g.alchemy.com/v2/Lmv_xbdd0nSBMkbWSz9kk` — READ-ONLY)
- `zk-proofs/hardhat.config.js`: `process.env.SEPOLIA_RPC_URL` for deployments

**Deployed Contracts (Sepolia):**
- `IdentityVerifier` (`Groth16Verifier`): `0x2625C6fDBEDcCD572836FfbFA391D2C25de7ae26` (hardcoded fallback in `zkp-backend/server.js`)
- `CredentialRegistry`: `0xB7a915C78C546A1082CB66bA294fAFee52E4EB07` (hardcoded fallback in `zkp-backend/server.js`)

**Contract Source Files:**
- `zk-proofs/contracts/CredentialRegistry.sol` — issues, revokes, and looks up credentials by rollNo or pubHash
- `zk-proofs/contracts/IdentityVerifier.sol` — Groth16 verifier generated by snarkjs; `verifyProof(pA, pB, pC, publicSignals)` → bool
- ABI artifacts at `zk-proofs/artifacts/contracts/CredentialRegistry.sol/CredentialRegistry.json` and `.../IdentityVerifier.sol/Groth16Verifier.json`

**On-chain Write Operations (admin backend only):**
- `registry.issueCredential(rollNo, ipfsCID, pubHashBytes32)` — called from `credentialService.issueCredentialOnChain()`
- `registry.revokeCredential(rollNo)` — called from `credentialService.revokeCredentialOnChain()`
- Signing wallet: `new ethers.Wallet('0x' + process.env.PRIVATE_KEY, provider)`

**On-chain Read Operations (zkp-backend only, no wallet needed):**
- `verifierContract.verifyProof(pA, pB, pC, publicSignals)` — Groth16 on-chain proof check
- `registryContract.getCredentialByHash(pubHashBytes32)` — credential registry lookup by pubHash

**Localhost / Hardhat node:** `http://127.0.0.1:8545` — used for local development with `zk-proofs/` scripts; `.env.example` default for zkp-backend

## IPFS / Pinata

**Service:** Pinata Cloud — JSON pinning only (no file uploads)

**API Endpoint:** `https://api.pinata.cloud/pinning/pinJSONToIPFS` (POST)

**Used by:** `privdId_admin/backend/services/credentialService.js` → `pinToIPFS(credential)`

**Auth:** `Authorization: Bearer ${process.env.PINATA_JWT}`

**Pinned data structure per credential:**
```js
{
  rollNo, programme, email, hashedData,
  issuedAt, issuer, type, version
}
```
Metadata name: `privid-credential-${rollNo}`

**Retrieval Gateway:** `https://gateway.pinata.cloud/ipfs/${ipfsCID}` — URL returned to verifier clients via `zkp-backend /credential-info` endpoint

**IPFS CID storage:** The CID returned from Pinata is anchored on-chain in `CredentialRegistry.issueCredential()` and stored in MongoDB on the student document.

## Email (SMTP)

**Service:** Configurable SMTP — defaults to Gmail (`smtp.gmail.com:587`)

**Used by:** `privdId_admin/backend/config/nodemailer.js`, `privdId_admin/backend/services/emailService.js`

**Trigger:** `POST /api/students/send-email` — admin sends credential links/passwords to students

**Config:** `EMAIL_HOST` (default `smtp.gmail.com`), `EMAIL_PORT` (default `587`), `EMAIL_USER`, `EMAIL_PASS`; port 465 → TLS, otherwise STARTTLS

## Database

**Provider:** MongoDB (Atlas or self-hosted)

**ODM:** Mongoose 8.14.2

**Connection:** `process.env.MONGO_URI` (required, no default) — configured in `privdId_admin/backend/config/db.js`

**Model:** `privdId_admin/backend/models/Student.js` — single collection storing student records including `hashedData`, `cid`, `txHash`, `blockNumber`

**Used by:** Admin backend only. ZKP backend and mobile app do not connect to MongoDB directly.

## Inter-service Communication

```
┌─────────────────────────┐      HTTP (LAN)        ┌─────────────────────────┐
│   digital-app           │ ──────────────────────► │  privdId_admin/backend  │
│   (Expo React Native)   │  EXPO_PUBLIC_ADMIN_...  │  port 5000              │
│                         │  _BACKEND_URL           │  /api/students/login    │
│                         │                         │  /api/students/:id      │
└─────────────────────────┘                         └─────────────────────────┘

┌─────────────────────────┐      HTTP (LAN)        ┌─────────────────────────┐
│   digital-app           │ ──────────────────────► │  zkp-backend            │
│   (proof generation &   │  EXPO_PUBLIC_BACKEND_   │  port 3001              │
│    verification)        │  URL                    │  /generate-proof        │
│                         │                         │  /verify                │
│                         │                         │  /verify-onchain        │
│                         │                         │  /credential-info       │
└─────────────────────────┘                         └─────────────────────────┘

┌─────────────────────────┐      HTTP              ┌─────────────────────────┐
│  privdId_admin/frontend │ ──────────────────────► │  privdId_admin/backend  │
│  (React + Vite)         │  VITE_API_BASE_URL      │  port 5000              │
│                         │  default:               │  /api/students/*        │
│                         │  localhost:5000/api     │  /api/admin/*           │
└─────────────────────────┘                         └─────────────────────────┘
```

**Services do NOT call each other** (except frontend→backend). The mobile app and admin frontend each call their respective backends independently.

**Admin backend external calls:**
- `POST https://api.pinata.cloud/pinning/pinJSONToIPFS` (Pinata)
- Sepolia RPC via `process.env.SEPOLIA_RPC_URL` (ethers.js)

**ZKP backend external calls:**
- Sepolia RPC via `process.env.BLOCKCHAIN_RPC_URL` (ethers.js, read-only)

**Shared artifacts across services (filesystem, not HTTP):**
- `zk-proofs/artifacts/contracts/CredentialRegistry.sol/CredentialRegistry.json` — ABI loaded by both admin backend (`credentialService.js`) and zkp-backend (`server.js`) via relative path (`../zk-proofs/artifacts/...`)
- `zk-proofs/artifacts/contracts/IdentityVerifier.sol/Groth16Verifier.json` — ABI loaded by zkp-backend
- `identity.wasm`, `identity_final.zkey`, `verification_key.json` — circuit artifacts loaded by zkp-backend (and optionally by digital-app for on-device proof generation)

## API Endpoints Reference

### privdId_admin/backend (port 5000)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/health` | Health check |
| POST | `/api/admin/login` | Admin authentication → JWT |
| POST | `/api/students/login` | Student login → student record |
| GET | `/api/students` | List all students |
| POST | `/api/students` | Add single student |
| POST | `/api/students/bulk` | Bulk add students (JSON array) |
| POST | `/api/students/upload` | Bulk upload via Excel file (multer) |
| POST | `/api/students/send-email` | Send credential emails to students |
| GET | `/api/students/:id` | Get student by ID |
| PUT | `/api/students/:id` | Update student by ID |
| DELETE | `/api/students/:id` | Revoke student credential by ID |

### zkp-backend (port 3001)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/` | Health check |
| POST | `/generate-proof` | Generate Groth16 proof from {name, rollNo, dob, phoneNo, branch} |
| POST | `/verify` | Off-chain snarkjs verification of {proof, publicSignals} |
| POST | `/verify-onchain` | On-chain Groth16 verification via Sepolia contract |
| POST | `/credential-info` | Look up credential in CredentialRegistry by pubHash |
