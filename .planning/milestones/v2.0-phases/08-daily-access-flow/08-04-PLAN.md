zkp-backend /generate-proof (existing, UNMODIFIED — verified contract):
  POST { attrs, salts, reveal, nonce, currentDateInt } -> { proof, publicSignals, salts }
  attrs = 7-key object: { name, rollNo, dob, programmeLevel, discipline, batch, email }
    !! Pitfall 3: decrypted JSON has `dobInt`; the request key MUST be `dob` -> attrs.dob = cred.dobInt
  salts  = the 7-string array from the decrypted credential (cred.salts)
    !! Pitfall 2: NEVER omit salts — server auto-generates fresh ones if absent, producing a proof
       that passes /verify but FAILS /verify-onchain (merkleRoot mismatch). Always pass cred.salts.
  reveal = name-keyed booleans, one per circuit attribute (name,rollNo,dob,programmeLevel,discipline,batch,email)
  currentDateInt = Number(new Date().toISOString().slice(0,10).replace(/-/g,''))  // YYYYMMDD

Decrypted credential JSON: { name, rollNo, dobInt, programmeLevel, discipline, batch, email, salts[7], merkleRoot, ... }

Plan 08-02 utils: unwrapDEK(envelopeBase64), decryptCredentialBlob(blob, dek). Plan 08-01 endpoint: GET /api/students/credential/:rollNo/blobs.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile → zkp-backend /generate-proof | Decrypted attrs/salts/nonce cross the wire (HTTPS) — never the DEK/privkey |
| incoming verifier QR request → checklist | Untrusted requested-fields list pre-checks boxes (but never auto-discloses) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-10 | Information Disclosure | Wrong reveal mapping silently discloses an unintended attribute | mitigate | REVEAL_KEY_MAP is locked by the Task-1 user-decision checkpoint; the circuit cryptographically enforces that unrevealed attrs never appear in publicSignals (revealMask/revealedValue), so app-side selection cannot over-disclose beyond the chosen keys. |
| T-08-11 | Spoofing / repudiation | A scanned verifier request auto-generates a proof without consent | mitigate | D-10: incoming requests only PRE-CHECK editable boxes; the explicit "Generate Proof" tap is the consent action — nothing is disclosed from a scanned request without the prover seeing/confirming the checklist. |
| T-08-12 | Tampering | Omitting salts produces an on-chain-invalid proof (Pitfall 2) | mitigate | Request construction always passes `salts: cred.salts` explicitly; verify gate greps for the explicit salts passthrough so a regression to server-side auto-salts fails the build. |
| T-08-SC | Tampering | npm installs | mitigate | No installs — react-native-qrcode-svg and crypto utils already present (Plan 08-02 / existing deps). |
