## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verifier ↔ prover (visual QR / manual paste) | Untrusted proof+nonce payloads cross an out-of-band channel between two devices |
| mobile → zkp-backend /session/nonce, /verify-onchain, /credential-info | Backend-tracked nonce session governs single-use anti-replay |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-13 | Spoofing / Replay | Client-invented nonce defeats anti-replay | mitigate | Step 1 obtains the nonce from POST /session/nonce (backend-tracked Map); the screen never fabricates a nonce. Single-use enforced server-side (validateAndConsume). |
| T-08-14 | Tampering | Calling /verify then /verify-onchain double-consumes the nonce (Open Question 3) | mitigate | Verify flow calls /verify-onchain ALONE (strictly stronger on-chain check) + /credential-info; the verify gate greps to ensure no /verify call was reintroduced. |
| T-08-15 | Tampering | Tampered proof QR in the visual channel | accept | A tampered Groth16 proof simply fails /verify-onchain's cryptographic check and surfaces "Proof Invalid" with a reason — no extra integrity wrapper needed (RESEARCH.md security domain). |
| T-08-16 | Information Disclosure | Dangling nav to a deleted screen crashes / leaks a half-built state | mitigate | Task 2's verify gate greps all of screens/ for references to the 4 deleted screens and fails the build if any remain; App.js references checked too. |
| T-08-SC | Tampering | npm installs | mitigate | No installs — react-native-qrcode-svg + expo-camera already present; this plan only edits/registers/deletes screens. |
</threat_model>
