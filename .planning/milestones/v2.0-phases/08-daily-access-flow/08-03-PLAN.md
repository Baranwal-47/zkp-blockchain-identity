zkp-backend /credential-info (existing, unmodified):
  POST /credential-info { pubHash: "<publicSignals[0] / merkleRoot decimal string>" }
  found:true  -> { found:true, rollNo, ciphertextCID, issuedAtMs, revoked, ipfsUrl, etherscanUrl }

  D-05 mapping: found && !revoked -> "Verified" (#22c55e); found && revoked -> "Revoked" (#ef4444);
                network/throw -> "Unable to verify" (#64748b, NOT red)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile → admin-backend /blobs + IPFS gateway | Untrusted network responses parsed and fed to on-device decrypt |
| mobile → zkp-backend /credential-info | On-chain status read; failure must degrade gracefully |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-07 | Information Disclosure | Decrypted credential / DEK in logs | mitigate | No console.log of dek or decrypted plaintext (grep gate); plaintext lives in component state only for render. |
| T-08-08 | Denial of Service / UX | /credential-info or RPC unreachable blanks the whole screen | mitigate | The on-chain status check is wrapped separately so a failure yields "Blockchain Status: Unable to verify" (#64748b) while the decrypted credential still displays — the status check cannot fail the whole screen (D-05 / UI-SPEC). |
| T-08-09 | Tampering | Tampered ciphertext/envelope from IPFS gateway | mitigate | Inherited from Plan 08-02: AES-GCM + ECIES auth tags fail closed; a tampered blob throws and lands in the error+retry state, never renders garbage. |
| T-08-SC | Tampering | npm installs | mitigate | No package installs in this plan — screen files only consume existing/Plan-08-02 deps. |
</threat_model>
