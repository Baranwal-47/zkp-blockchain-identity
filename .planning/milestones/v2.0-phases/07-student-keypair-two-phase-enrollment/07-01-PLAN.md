  <behavior>
    - wrapDEK(pubKeyHex, dek): given a 32-byte Buffer dek and a valid secp256k1 compressed pubkey hex, returns a base64 string envelope; throws if dek is not a 32-byte Buffer; throws if pubKeyHex is not a non-empty string.
    - unwrapDEK(privKeyHex, envelopeBase64): given the matching private key hex and the base64 envelope, returns the original 32-byte DEK Buffer; throws if the decrypted DEK length != 32.
    - Round-trip: wrapDEK then unwrapDEK over a fresh `new PrivateKey()` recovers the original DEK byte-for-byte (Buffer.compare === 0).
    - wrapDEK logs a `[perf] wrapDEK: N s` line via timed(); it never logs the DEK or any key material.
  </behavior>
  <action>Create `privdId_admin/backend/crypto/ecies.js` mirroring `aesgcm.js` exactly. Import `{ encrypt, decrypt }` from `eciesjs` and `{ timed }` from `../utils/timing.js`. Define `const DEK_LENGTH = 32`. Open with the project's crypto-module doc-comment convention: cite blueprint §E3.6, name the envelope shape (base64 of eciesjs output = ephemeral pubkey + IV + ciphertext + MAC), and a THREAT MITIGATIONS list referencing T-07-01 (replay re-wrap, mitigated downstream by the D-06 phase guard), T-07-02 (malformed pubKeyHex DoS, mitigated by sync input validation), T-07-03 (key material in logs, mitigated by never logging the DEK). Export async `wrapDEK(pubKeyHex, dek)`: validate `Buffer.isBuffer(dek) && dek.length === DEK_LENGTH` (throw `wrapDEK: expected a ${DEK_LENGTH}-byte Buffer dek`) and `typeof pubKeyHex === "string" && pubKeyHex.length` (throw `wrapDEK: pubKeyHex must be a non-empty hex string`) SYNCHRONOUSLY first, then `const { out } = await timed("wrapDEK", async () => encrypt(pubKeyHex, dek).toString("base64"))` and return `out`. Export `unwrapDEK(privKeyHex, envelopeBase64)` (synchronous, no timed() — it has no server-side caller this phase but completes the symmetric module): `Buffer.from(envelopeBase64, "base64")`, `decrypt(privKeyHex, envelope)`, validate decrypted length === DEK_LENGTH (throw on mismatch), return the Buffer. Do NOT wrap encrypt/decrypt in a try/catch — let auth-tag failures propagate to the caller's error middleware, exactly as `aesgcm.js::decryptCredential` does. Note: `eciesjs` must be installed in this task — run `cd privdId_admin/backend && npm install eciesjs@^0.5.0` (0.5.x pure-JS line per 07-RESEARCH.md State of the Art; do NOT resolve to ^0.3.x).</action>
