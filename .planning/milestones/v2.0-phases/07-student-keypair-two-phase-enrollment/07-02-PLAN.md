<objective>
Implement the student-claim half of two-phase enrollment: the `POST /students/:id/pubkey` endpoint and its service orchestration. On a valid claim against an `awaiting-keypair` student, the backend ECIES-wraps the escrowed DEK to the submitted pubkey, pins the wrapped envelope to IPFS as `dekEnvelopeCID`, then in a single atomic write wipes the plaintext `dek`, stores `dekEnvelopeCID`, and flips `enrollmentPhase` to `"active"`. This closes ENROLL-02 and the backend side of KEY-02, and ends single-custody of the DEK.

Purpose: Closes ENROLL-02 (claim wraps + pins + wipes + flips) and the backend half of KEY-02 (accepts only the pubkey, never a private key). Enforces D-06's one-time-claim guard and Pitfall 4's pin-first-then-atomic-write ordering.
Output: Modified `credentialService.js` (exported envelope-pin helper), `studentService.js` (claimCredential), `studentController.js` (claimPubkey), `routes/studentRoutes.js` (new route).
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-07-01 | Tampering / Elevation | POST /:id/pubkey re-wrap | mitigate | D-06 one-time-claim guard implemented as `enrollmentPhase: "awaiting-keypair"` in the findOneAndUpdate filter (atomic, closes TOCTOU); repeat claim -> 409 |

| T-07-03 | Information Disclosure | dek in claim response/logs | mitigate | sanitizeStudent excludes dek; no logging of dek/dekBuffer; KEY-02 design means backend never receives a private key |
| T-07-05 | Repudiation/Integrity | claim with no held DEK | mitigate | Fail loudly (AppError) if student.dek is absent; never regenerate the DEK (Phase 6 decision) |
